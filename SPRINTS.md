# Sprint 1 — Foundation UI

## Objective

Build the reusable shell for the entire Barons Platform.

Every page should inherit the same navigation, footer, layout, branding, and design language.

---

## Deliverables

- [ ] Create `src/config/site.ts`
- [ ] Create `src/data/navigation.ts`
- [ ] Build `Header.astro`
- [ ] Build `Footer.astro`
- [ ] Update `Layout.astro`
- [ ] Verify responsive navigation
- [ ] Verify mobile layout

---

## Engineering KPI

- Shared layout across all pages
- No duplicated navigation
- Responsive on desktop and mobile
- Configuration-driven navigation

---

## Business KPI

- Barons branding established
- Discovery Call CTA visible
- Website begins reflecting the BOSS Framework

---

## User KPI

A first-time visitor can understand:
- Who Barons is
- Where to go next
- How to contact us

...within five seconds.

- The Barons Brand
- The BOSS Framework

- Measurable Business Outcomes

---

# Success Metrics

The Barons Platform should always answer four questions:

1. Who are we?
2. What problems do we solve?
3. Why should someone trust us?
4. What should they do next?

If a page cannot answer at least one of these questions, it should be redesigned.

---

# Remember

We are not building pages.

We are building a platform.

We are not selling software.

We are helping businesses build systems that scale.

Technology is the tool.

Confidence is the outcome.

# The CSA Question

Before every feature, ask:

Why are we building this?

How does it support the BOSS Framework?

How will we measure its success?

Can it be reused?

Does it make the platform better?

If we cannot answer these questions, the feature is not ready to build.
